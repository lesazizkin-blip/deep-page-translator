# Deep Page Translator

Расширение для Chrome (Manifest V3), которое переводит то, что пропускает
встроенный переводчик Chrome:

- содержимое **cross-origin iframe** (например, уроки и ноутбуки Kaggle с домена `*.kaggleusercontent.com`);
- текст внутри **Shadow DOM** (open, а через `chrome.dom.openOrClosedShadowRoot` — и closed);
- контент, который появился **после загрузки** (SPA, ленивая подгрузка, раскрывающиеся блоки).

Чистый JavaScript, без сборщиков и зависимостей.

## Установка

1. Откройте [последний релиз](https://github.com/lesazizkin-blip/deep-page-translator/releases/latest)
   и скачайте архив `deep-page-translator-vX.Y.Z.zip`. Распакуйте его в постоянное место: папку потом
   не удаляйте и не перемещайте, Chrome читает файлы расширения прямо из неё.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика** (переключатель справа вверху).
4. Нажмите **Загрузить распакованное** и выберите распакованную папку (в ней лежит `manifest.json`).
5. Закрепите значок расширения на панели (иконка пазла → булавка).

Можно поставить и из исходников: **Code → Download ZIP** (или `git clone`), затем на шаге 4 выбрать
вложенную папку `page-translator`.

**Обновление:** распакуйте новый релиз поверх старой папки (с заменой файлов), нажмите ⟳ в карточке
расширения в `chrome://extensions` и перезагрузите открытые вкладки. Настройки и кеш сохранятся.
Что изменилось — в [CHANGELOG.md](CHANGELOG.md).

Уже открытые вкладки нужно перезагрузить: content scripts внедряются при загрузке страницы.

## Использование

- **Popup** (клик по значку): «Перевести страницу» / «Показать оригинал», язык перевода
  (по умолчанию русский), провайдер, переключатель «Автоматически переводить на этом сайте».
- **Горячие клавиши** переключают перевод на текущей вкладке. Их два вида:
  - **сочетание Chrome** (по умолчанию `Alt+T`): работает, даже когда фокус в адресной строке;
    меняется на `chrome://extensions/shortcuts`;
  - **своё сочетание** в настройках расширения → «Горячие клавиши»: нажмите на поле и затем нужные клавиши.
    Подходит любое сочетание с Ctrl/Alt/Meta (например, `Ctrl+Shift+Y`) или `F1`–`F12`.
    Оно работает в любой раскладке (русской и английской) и внутри iframe, например в уроке Kaggle.
    Применяется сразу, перезагружать расширение не нужно.
- **Контекстное меню** → «Перевести выделенное»: перевод появляется во всплывающем окне рядом с выделением
  (работает и внутри iframe).
- **Подсказка с оригиналом**: наведите курсор на переведённый абзац и подождите ~0,6 с. Отключается в настройках.
- **Индикатор** в правом нижнем углу показывает прогресс по всем фреймам и ошибки (с кнопкой «Повторить»).

## Настройки (страница «Параметры»)

| Параметр | Описание |
|---|---|
| Провайдер | Google (по умолчанию, без ключа), встроенный в Chrome, DeepL, LibreTranslate |
| DeepL API-ключ | Ключ с окончанием `:fx` — бесплатный тариф (api-free.deepl.com), иначе Pro |
| LibreTranslate URL / ключ | Адрес своего сервера, например `http://localhost:5000` |
| Автоперевод | Список хостов, где перевод включается сам (`kaggle.com` покрывает поддомены) |
| Исключённые сайты | На них автоперевод не включается, а их iframe не переводятся |
| Подсказка с оригиналом | Вкл/выкл |
| Своя горячая клавиша | Сочетание для перевода страницы, записывается нажатием |
| Не переводить | Свои слова и фразы, которые остаются как есть (например, «Feature Engineering») |
| Кеш | Статистика и кнопка очистки |

Кнопка «Проверить провайдера» делает пробный перевод и показывает понятную ошибку
(нет ключа, неверный ключ, кончилась квота, сервер недоступен, лимит запросов и т.д.).

### Провайдеры

1. **Google Translate**: неофициальный endpoint `translate.googleapis.com/translate_a/t?client=gtx`
   с `format=html`. Ключ не нужен. Endpoint недокументированный: Google может ограничить
   частоту запросов (HTTP 429, расширение повторяет запрос с паузой) или изменить API.
2. **Встроенный в Chrome** (Translator API, Chrome 138+, on-device). Перевод выполняется локально.
   Модель для пары языков при первом использовании скачивается, и Chrome требует для этого
   клика пользователя по странице. Поэтому в индикаторе появится кнопка «Загрузить модель».
   Язык источника определяется через LanguageDetector API (если его нет, считается английским).
   HTML этот API не поддерживает, поэтому абзацы с inline-разметкой переводятся по узлам.
3. **DeepL API**: официальный API, `tag_handling=html`.
4. **LibreTranslate**: свой сервер, `format=html`.

Новый провайдер добавляется так: класс-наследник `Provider` из `background/providers/base.js`
и регистрация в `background/providers/index.js`.

## Как это работает

```
 ┌──────────── вкладка ─────────────────────────────┐
 │ главный фрейм        iframe (другой домен)       │
 │ content script       content script              │   all_frames + match_origin_as_fallback:
 │  ├ обход DOM          ├ обход DOM                │   скрипт внедряется в каждый фрейм
 │  ├ индикатор          └ …                        │
 │  └ Translator API (для встроенного провайдера)   │
 └────────┬──────────────────┬──────────────────────┘
          │ pt:translate     │  (пачки HTML-строк)
          ▼                  ▼
 ┌──────── service worker ──────────────────────────┐
 │ кеш LRU (storage.local) → очередь → провайдер    │
 │ батчи по лимиту символов/строк, повтор с паузой  │
 │ сводный прогресс → главный фрейм                 │
 └──────────────────────────────────────────────────┘
```

**Сбор текста.** `TreeWalker` обходит DOM и отбрасывает целые поддеревья (`FILTER_REJECT`):
`script`, `style`, `noscript`, `code`, `textarea`, `input`, `[contenteditable]`,
`[translate="no"]`, `.notranslate`, формулы KaTeX/MathJax (`.katex`, `mjx-container`, …),
ячейки кода и вывода Jupyter (`.jp-CodeCell .jp-Cell-inputWrapper`, `.jp-OutputArea`, …),
редакторы (CodeMirror, Monaco). На каждом хосте shadow DOM обход рекурсивно заходит в `shadowRoot`.

`<pre>` с кодом (подсветка синтаксиса, `<code>` внутри, много символов вроде `{}();=`) пропускается.
`<pre>` с обычным текстом (так GitHub показывает `LICENSE` и `.txt`) переводится по абзацам:
жёсткие переносы строк и отступы сохраняются, центрированные заголовки переводятся построчно.

Ещё переводятся атрибуты `placeholder` (подсказка в поле поиска) и `title` (всплывающая подсказка),
после основного текста.

**Не переводятся названия.** Встроенный список (Python, pandas, NumPy, scikit-learn, Kaggle, GitHub…)
и свой список из настроек оборачиваются в `notranslate`, поэтому тег «pandas» не становится «панды».

**Группировка по блокам.** Каждый текстовый узел относится к ближайшему не-inline предку
(`p`, `li`, `h1`–`h6`, `td`, `div`, …). Блок отправляется как HTML, в котором каждый текстовый узел
обёрнут в `<b id=N>`:

```html
<b id=0>Use</b> <b id=1 class="notranslate">pd.read_csv</b> <b id=2>to load</b> <b id=3>the data</b>
```

Переводчик видит предложение целиком и переводит по смыслу, сохраняя теги. Содержимое
`<code>`, формулы и элементы с `translate="no"` помечены `notranslate`: переводчик видит их
как контекст, но не меняет.

Затем перевод раскладывается обратно по текстовым узлам через `node.data`. Узлы внутри ссылок
и выделения получают текст своих тегов, а текст между ними раскладывается по промежуткам
в порядке перевода. Поэтому предложение, где переводчик переставил части
(«Read <a>the guide</a> before you start» → «Прежде чем начать, прочтите <a>руководство</a>»),
остаётся правильным. Элементы страницы не пересоздаются, так что вёрстка, ссылки и обработчики
событий остаются на месте. Если переводчик потерял теги или числа, узлы такого блока
переводятся по одному.

**Отдельные пункты.** Вкладки, кнопки, теги и пункты меню, стоящие рядом без своего текста
между ними, переводятся по одному, а не как одна фраза. Иначе вкладки «Tutorial | Data»
превратились бы в «Учебные | данные».

**Порядок.** Каждый блок в очереди наблюдается через `IntersectionObserver`. Сначала уходят
видимые блоки (с запасом 300 px), потом остальные.

**Новый контент.** `MutationObserver` на документе и на каждом shadow root
(debounce 300 мс, не дольше 1 с) переводит добавленные узлы и изменённый сайтом текст.
Собственные изменения расширения отсекаются: текст узла совпадает с сохранённым переводом.
Через 1,5 и 5 с после включения выполняется повторный проход, он ловит shadow roots,
прикреплённые позже.

**Оригинал.** Для каждого узла в `WeakMap` хранится `{orig, tr}`. «Показать оригинал» возвращает
`orig`, повторное включение мгновенно возвращает `tr` без запросов к сети. Уже переведённые узлы
повторно не переводятся.

**Кеш.** Он хранится в `chrome.storage.local` под ключом «провайдер + язык + хеш текста».
Это LRU с лимитом 30 000 записей / 2,5 млн символов, запись на диск отложенная.
Кеш общий для всех фреймов и вкладок.

## Почему встроенный переводчик Chrome не справляется

- **Cross-origin iframe.** Переводчик Chrome работает в процессе страницы и переводит документ
  главного фрейма. Фрейм с другого домена (site isolation) — это отдельный документ, часто
  в отдельном процессе, со своим языком и своим состоянием перевода. На Kaggle текст урока
  отображается в iframe с `*.kaggleusercontent.com`, поэтому интерфейс Kaggle переводится,
  а сам урок — нет. Расширение внедряет content script в каждый фрейм (`all_frames`,
  `match_origin_as_fallback`) и переводит каждый документ отдельно, через общий background.
- **Shadow DOM.** Текст в shadow tree не виден обычному обходу DOM (`childNodes`, `querySelectorAll`
  и TreeWalker не заходят внутрь), а веб-компоненты встречаются всё чаще.
- **Динамический контент.** Переводчик Chrome ловит не все изменения после первоначального
  перевода: при перерисовке в SPA, догрузке и раскрытии блоков текст остаётся на исходном языке
  или «откатывается».

## Ограничения

- Не работает на служебных страницах (`chrome://`, Chrome Web Store, PDF-просмотрщик).
- Для `file://` нужно включить «Разрешить доступ к URL файлов» в карточке расширения.
- Inline-элементы со свойством `display: block` через CSS (например, `span` в роли абзаца)
  попадают в блок родителя: перевод выйдет общим, но разметка сохранится.
- Google-endpoint неофициальный, при интенсивном использовании возможен временный лимит (429).
- Качество перевода терминов зависит от провайдера: Google переводит ML-термин «feature» как «функция»
  вместо «признак». Термин можно оставить по-английски через «Не переводить» в настройках
  или попробовать DeepL.
- Перевод бывает длиннее оригинала, и в кнопках фиксированной ширины текст может не поместиться.
- Если сайт пересоздаёт DOM при каждом обновлении (некоторые виртуальные списки), перевод
  повторяется. Повторные переводы берутся из кеша, без сети.
